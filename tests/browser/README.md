# 浏览器交互测试

运行 `npm run test:e2e` 会构建真实 Go 服务，启动临时本地模型 HTTP 服务，然后以 Chrome/Chromium 遍历页面。测试使用独立 Cookie 用户空间，数据目录在退出时清理。浏览器结果包含逐项断言、完整截图、JSON 汇总和 HTML 图库。

`fixture.mjs` 提供五种模型协议的本地响应与可控故障。`[slow]` 延迟三秒，`[once]` 对同一完整提示词首次返回 503，`[fail]` 持续返回 503，`[invalid]` 返回不合格式的模型内容，`[long]` 生成长回答用于滚动测试。应用请求仍经过正常路由、模型解析、卡片存储和 SSE 回传。

手机手势验证采用 Chromium 的真实触摸事件与设备仿真。`npm run test:webkit` 使用真实 WebKit 引擎运行 models、platform、experience 和 native_web；先执行 `npx playwright install webkit`。短视口检查软键盘占用屏幕后的布局，真实 iOS/Android 键盘、操作系统分享及安装仍需真机验证。模型网络协议在本地测试服务上验证，外部服务的密钥和回答质量需针对实际部署单独验证。

平台套件用 `network-gateway.mjs` 将浏览器请求转发给真实 Go 服务，并实际断开连接以验证 Service Worker 缓存回退。它没有模拟模型或修改响应内容，也不依赖浏览器的 `setOffline` 标记。这避免 [Playwright 已确认的 WebKit 离线模拟缺陷 #42775](https://github.com/microsoft/playwright/issues/42775)：该开关会在 Service Worker 有机会响应前拦截导航。请求建立前刷新另有独立测试，验证问题在当前标签的 sessionStorage 中恢复，不会自动发送。

调试时可以先启动 `node tests/browser/fixture.mjs`，然后设置其输出地址为 `GITCHAT_TEST_URL` 运行单个套件。若外部地址指向已有应用，测试会在该应用中新建测试用户和对话。
